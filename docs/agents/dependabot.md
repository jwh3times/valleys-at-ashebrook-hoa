# Dependabot

Settings the shared `dependabot` skill reads (installed from `jwh3times/skills`, ADR 0029). Each
`##` heading is one setting; the prose around them is read too. How the pipeline and the Worker
types gate work is in [`ci-and-release.md`](./ci-and-release.md), and the steps around a merge are
in [`merging.md`](./merging.md).

## Stack

- An Astro 7 SSR app (`output: 'server'` in `astro.config.mjs`) on Cloudflare Workers through
  `@astrojs/cloudflare`, with React 19 through `@astrojs/react`. It is backed by D1 (SQLite through
  Drizzle ORM), R2 and KV, bound in `wrangler.toml`. Auth is Better Auth with
  `better-auth-cloudflare`; the board's document assistant calls Anthropic through
  `@anthropic-ai/sdk` (`src/server/ai/`). Cloudflare Workers Builds deploys `main` outside Actions
  (ADR 0004).
- Node 26.4.0 from `.nvmrc` (`engines` is `>=26.4.0`), npm, one manifest at the root. The root
  compiler is TypeScript 7; `npm run check` also runs `@astrojs/check` on TypeScript 6 from
  `vendor/astro-check-ts6/`.
- `.github/dependabot.yml` updates npm and GitHub Actions at `/` only. npm majors travel in four
  groups: `astro-ecosystem` (`astro`, `@astrojs/*`), `react` (`react`, `react-dom`, `@types/react`,
  `@types/react-dom`), `testing-library` (`@testing-library/*`) and `vite-ecosystem` (`vite`,
  `vitest`, `@vitejs/plugin-react`, `@vitest/*`); every other major arrives alone. Minor and patch
  bumps go to the `oxlint` group (`oxlint`, `oxlint-tsgolint`) or the `npm-minor-and-patch`
  catch-all, and actions to `actions-minor-and-patch`.
- A PR's checks: `build` (`.github/workflows/build.yml`), the changelog check
  (`.github/workflows/changelog.yml`), CodeQL's default setup, and Cloudflare's `Workers Builds`.
  `.github/workflows/version.yml` runs only on a push to `main`.

## Label

Valleys at Ashebrook HOA

## Review triggers

- `oxlint` and `oxlint-tsgolint`, any minor: `.oxlintrc.jsonc` enables the `correctness` category
  wholesale, so a rule a release adds to it or moves into it fails `npm run lint` on code nobody
  touched (#267, #536; `ci-and-release.md`, `merging.md`). They arrive as the `oxlint` group's own
  PR.
- `vitest` and `@vitest/*`, any minor: Vitest 5.1 broke every Workers-pool suite with a `vi.mock()`
  factory, because its module mocker calls `AsyncLocalStorage#disable()`, which workerd does not
  implement, though every peer range matched (#533, `ci-and-release.md`).

## Resolution

```bash
nvm install "$(cat .nvmrc)" && nvm use "$(cat .nvmrc)"   # Node 26.4.0
npm ci
```

At the root, as `build.yml` runs it after `actions/setup-node` with `node-version-file: .nvmrc`.
Its `postinstall` installs the second lockfile, `vendor/astro-check-ts6/package-lock.json`, with
`npm ci --ignore-scripts`; Dependabot does not update that directory. Never approve dependency
install scripts to make an install pass: that is confirmation-gated (`AGENTS.md`, Deploy).

## Where to look

- `.github/workflows/build.yml`, `changelog.yml` and `version.yml`: the `with:` inputs of
  `actions/checkout`, `actions/setup-node` and `actions/create-github-app-token`, each pinned to a
  commit SHA with its version in a trailing comment.
- `astro.config.mjs` (the adapter and the React integration), `vitest.config.ts`,
  `vitest.workers.config.ts` and `vitest.shared.ts`, `wrangler.toml` and `wrangler.test.toml`,
  `drizzle.config.ts`, `.oxlintrc.jsonc`, `.prettierrc.json`, `tsconfig.json` and
  `tsconfig.node.json`.
- `vitest.workers.config.ts` merges Astro's Vite plugins into the Workers test pool, dropping the
  Cloudflare one through `isCloudflarePlugin` in `vitest.shared.ts`, which matches any plugin
  whose name contains `cloudflare`. A plugin rename in `astro`, `@astrojs/cloudflare` or
  `@cloudflare/vite-plugin` breaks it.
- `worker-configuration.d.ts`: generated by `wrangler types` from the runtime types bundled in
  `wrangler`, committed, and compared by `build.yml`'s last step.
- `package.json`: `overrides.miniflare` holds caret floors for `undici` and `sharp`
  (`ci-and-release.md`), and the `auth:generate` script pins the Better Auth CLI as `auth@1.7.3`,
  apart from `better-auth`.
- `vendor/astro-check-ts6/package.json`: pins `@astrojs/check` and TypeScript 6 for the `.astro`
  diagnostics, outside Dependabot's directories.
- Source: `src/server/` (server-only: `auth/`, `db/`, `ai/`), `src/pages/` (pages and API
  routes), `src/worker.ts` (the Worker entry, `main` in `wrangler.toml`), `src/middleware.ts`, and
  `test/`.

## Grounding facts

- The database is Cloudflare D1. There is no Postgres, no database or runtime image, and no
  Dockerfile or compose file. Schema changes are hand-authored SQL migrations in
  `src/server/db/migrations/`, applied by `wrangler d1 migrations apply` (the `db:migrate:*`
  scripts); deploys never apply them. `npm run db:generate` is not part of the workflow
  (`AGENTS.md`): never run it to judge a `drizzle-kit` bump.
- Every job runs on `ubuntu-latest` under the Node `.nvmrc` names.
- `version.yml` runs only on a push to `main`, so a PR's CI never runs its steps. A green `build`
  covers the actions in `build.yml` and `changelog.yml`, not `version.yml`'s use of
  `actions/create-github-app-token` (`client-id`, `private-key`, `permission-contents`) or of
  `actions/checkout` (`ref`, `fetch-depth`, `token`): read those inputs against the release notes.
- `astro` and `@astrojs/*` share majors. `@astrojs/cloudflare` hard-peers on `astro` `^7.4.0` and
  `wrangler` `^4.125.0`, and `@cloudflare/vite-plugin` on `wrangler` `^4.156.1`
  (`package-lock.json`).
- `better-auth` depends on `@better-auth/core` and `@better-auth/drizzle-adapter` at its own exact
  version, and `better-auth-cloudflare` 0.4.1 hard-peers on `better-auth` and
  `@better-auth/drizzle-adapter` `^1.5.0` (`package-lock.json`). `.github/dependabot.yml` has no
  major group for them, so a Better Auth major arrives as separate PRs, and is blocked while
  `better-auth-cloudflare` has no release that widens that range.
- `@cloudflare/workers-types` is a types-only devDependency. No package hard-peers on it (`wrangler`
  and `drizzle-orm` list it as an optional peer), and `wrangler types` does not read it, so its bump
  on its own has not drifted `worker-configuration.d.ts` (#503, #515, #521).
- `@vitejs/plugin-react` hard-peers on `vite` `^8.0.0`, `@astrojs/vite-plugin-astro` on `vite`
  `^8.3.3`, and `@cloudflare/vitest-plugin` on `vitest` `^4.1.0 || ^5.0.0` (`package-lock.json`).
  A `vitest` major needs the plugin's range first: #308 failed `npm ci` on its predecessor's peer.
- CodeQL on a PR whose head commit is Dependabot's comes back neutral, "configurations not found",
  with no analysis run. That is expected and does not block the merge (`ci-and-release.md`).

## Playbook

CI's gates, in its order: `npm run types:worker` (regenerate), `npm run format:check`,
`npm run lint`, the repository's own lints (`ci-and-release.md`), `npm run check`, `npm test`,
`npm run test:server`, `npm run build`, `npm run deploy:check`, then the Worker types drift
verdict.

- **Worker types drift**, on any bump that moves `wrangler` or `workerd`, including through the
  lockfile alone (#555): `build` passes every suite, then its last step fails with
  `worker-configuration.d.ts is out of date. Run 'npm run types:worker' and commit the result.`
  The fix, on the PR branch: `npm ci && npm run types:worker`, then commit
  `worker-configuration.d.ts` as `chore: regenerate worker types for workerd <version>`, the
  version read from the regenerated file's header. `npm run types:worker:check` confirms it, and
  `build` goes green with no other change. It worked on #581 and #583, and is the fix the verdict
  on #614 names. The route without an install, applying the diff from the failing log, is in
  `merging.md`.
- **oxlint** (`oxlint` group): the gate is `npm run lint`. A new `correctness` rule that fails on
  real code is fixed in the code on the Dependabot branch, never by disabling the rule (#536). A
  local `Rule '…' not found in plugin` is a stale `node_modules`: reinstall.
- **Vitest** (`vitest`, `@vitest/*`, `@cloudflare/vitest-plugin`): `npm test` and the full
  `npm run test:server`. Before a `vitest` major, read `@cloudflare/vitest-plugin`'s `vitest` peer
  range from the lockfile.
- **Astro major** (`astro-ecosystem` group): keep `astro` and every `@astrojs/*` on one major. Read
  the upgrade guide for each major crossed, then `astro.config.mjs` and `vitest.shared.ts`. Gates:
  `npm run check`, `npm test`, `npm run test:server` (it renders `.astro` pages through the Astro
  Container API in the Workers runtime), `npm run build`, `npm run deploy:check`.
- **Cloudflare tooling** (`wrangler`, `@cloudflare/vitest-plugin`, `@cloudflare/workers-types`):
  `wrangler` drives `types:worker`, `deploy:check` and the local D1 migrations. Check the hard
  peers on `wrangler` above. Gates: `npm run types:worker:check`, `npm run test:server`,
  `npm run build`, `npm run deploy:check`.
- **Drizzle** (`drizzle-orm`, `drizzle-kit`): the schema files are listed in `drizzle.config.ts`.
  Gates: `npm run check`, `npm run test:server` (its suites apply the migrations to D1 through
  `applyD1Migrations`), `npm run lint:migrations`.
- **Better Auth** (`better-auth`, `@better-auth/core`, `@better-auth/drizzle-adapter`,
  `better-auth-cloudflare`): review their PRs together and check the peers above. The config is
  `src/server/auth/index.ts`; `npm run auth:generate` writes `src/server/db/auth-schema.ts` with
  the separately pinned CLI, and a change there is a schema change, so a hand-authored migration
  (`migrations.md`). Gates: `npm run check`, `npm run test:server`.
- **Other build-critical majors** (the `react` group, `typescript`, `@anthropic-ai/sdk`,
  `prettier` and `prettier-plugin-astro`): the `Resolution` install, then CI's gates from
  `npm run format:check` through `npm run build`. A `typescript` bump moves the root compiler only;
  the `.astro` checker stays on the vendored TypeScript 6.
- **GitHub Actions major:** CI is the gate for `build.yml` and `changelog.yml`; read
  `version.yml`'s inputs by hand. A Node-runtime or runner-version bump alone is not a break.
  NEEDS EFFORT only when a removed or renamed input, or a changed default, reaches a `with:` use;
  name the step.
